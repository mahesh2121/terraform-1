# Terraform 100 Production Issues with STAR Method and Solutions

This document lists 100 common Terraform issues seen in production environments. Each issue includes a clearly labeled **Solution** column and is written using the STAR method:

- **Situation**: What happened or what risk exists.
- **Task**: What the team must protect, fix, or improve.
- **Action**: What was done to fix or prevent the issue.
- **Solution**: In the table below, the **Solution** column contains the exact fix or best-practice approach for each issue.
- **Result**: Expected production outcome.
- **Production use case**: Where this matters most.

> Use this as an interview preparation guide, incident runbook seed, production readiness checklist, or Terraform operating model reference.

## Production readiness checklist

Use the following checklist before applying Terraform to production:

1. Remote state is encrypted, versioned, backed up, access-controlled, and locked.
2. Terraform CLI and provider versions are pinned and tested.
3. Plans are generated in CI and reviewed before apply.
4. Production applies use protected branches, approvals, and the exact reviewed plan.
5. Destructive changes are highlighted and guarded with lifecycle rules where appropriate.
6. Secrets are stored in a secret manager and not exposed through outputs or logs.
7. Tags, naming, ownership, and cost metadata are standardized.

Situation: In production, we found that two pipelines could apply the same state at the same time.
