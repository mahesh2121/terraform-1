# AWS Solution Architecture 100 Tasks with STAR Solutions

This document contains 100 production-focused AWS solution architecture tasks written in STAR style.

- **Situation**: The real production scenario or architecture problem.
- **Task**: The design objective or responsibility.
- **Solution**: The architecture action or best-practice design.
- **Result**: The expected business or technical outcome.
- **Production use case**: Where the pattern is commonly used.

> Use this guide for AWS Solutions Architect interview preparation, design reviews, production architecture planning, migration discussions, and incident postmortems.

## Production architecture checklist

Use this checklist before approving an AWS production design:

1. Accounts are separated by environment, workload, and security boundary.
2. IAM uses least privilege, federation, MFA, and short-lived credentials.
3. VPC CIDRs do not overlap with current or future networks.
4. Public resources are intentionally public and protected by WAF, TLS, and logging.
5. Compute runs across multiple Availability Zones where availability requires it.
6. Databases have backups, encryption, monitoring, and tested restore procedures.
7. Logs, metrics, traces, and audit events are centralized with retention policies.
8. Secrets are stored in Secrets Manager or Parameter Store and rotated where possible.
9. Disaster recovery targets define RTO, RPO, region strategy, and failover process.
10. Cost allocation tags, budgets, and anomaly detection are enabled.
11. Infrastructure is managed as code with peer review and policy checks.
12. Architecture has been reviewed against the AWS Well-Architected pillars.

Situation: A production web application was running in a single Availability Zone and had frequent downtime during maintenance events.
